# Home Groups Analytics

Тёмный дашборд по сети домашних групп: состояние, география, ведущие, жизненный цикл.
Один самодостаточный файл `home-groups.html` — открывается двойным щелчком, работает офлайн
(кроме шрифтов Google Fonts, без них подставится системный гротеск).

## Откуда данные

Единственный источник — **база**. Таблица `groups` (116 строк из выгрузки + заведённые здесь
и через бота), `requests` (233 строки листа ЗАЯВКИ + заявки бота), `coordinators`.

Сервис дашборда читает их на каждый запрос страницы и кладёт в `window.HG_LIVE` перед
основным скриптом. В самом файле данных больше нет: он весит 77 КБ вместо 267 КБ и при
открытии без сервера показывает пустые состояния. Это заодно значит, что телефоны и адреса
не лежат в файле, которым можно случайно поделиться.

### Как обновить выгрузку из таблицы

```
python3 dashboard/tools/extract.py "Домашняя группа (Ответы).xlsx" > dashboard/data.json
npm run import:spreadsheet
```

Импорт идемпотентен: удаляет ранее импортированное (`source='таблица'` / `origin='таблица'`)
и вставляет заново. Не upsert-ом — у 32 групп из 116 нет номера в реестре, естественного ключа
не существует, а в листе есть настоящий дубль, и сверка по содержимому его потеряла бы.
Заведённое через дашборд (`ui`) и через бота (`бот`) импорт не трогает.

Пересобирать образ для обновления данных больше не нужно.

## Какие поля переносятся

Лист «МАЛЫЕ ГРУППЫ (2026)» переносится целиком, все девятнадцать столбцов: №, ФИО ведущего,
приём новых, телефон, возраст, район, метро, адрес, состав, день, время, количество человек,
координатор, дата обратной связи, комментарий, обучение, формат, статус, проверено.

В шапку таблицы влезает семь столбцов, остальное — в раскрывающейся строке: клик по строке
показывает всё, что записано о группе. Телефоны выведены ссылками `tel:`, чтобы с телефона
можно было звонить сразу из дашборда.

**Это персональные данные.** Адрес в исходной таблице помечен «только для внутреннего
пользования, людям не давать», телефоны — тем более. Поэтому дашборд закрыт паролем, отдаётся
с `noindex` и запретом встраивания во фрейм. Делиться им можно только по адресу с паролем;
ссылку-артефакт, если она у вас есть, кому попало отдавать нельзя — там те же данные.

### Чем телефоны неудобны в исходной таблице

Три случая, которые пришлось разбирать отдельно, — если появятся новые, смотрите `phones()`
в `tools/extract.py`:

| В таблице | Что с этим |
| --- | --- |
| `8.900111222E10` | Google-таблица сочла номер числом; восстанавливаем цифры |
| `8 (900) 111-22-33 Мария; 8 (900) … Ольга` | два номера с именами: имена сохраняем, номера вытаскиваем оба |
| `89001112233 89004445566` | два номера через пробел, без разделителя |
| `(+) (358 45) 000-11-22` | зарубежный номер: код страны свой, `+7` не подставляем |

Время лежит долей суток (`0.7916…` = 19:00), но местами записано текстом (`19.00`), а иногда
это вообще слово — «Вечер», «День». Слова оставляем как есть.

## Создание групп и заявок

Вкладка «Добавить» в шапке. Две формы:

- **Группа** — все девятнадцать столбцов листа. Обязательны ведущий, район, формат и статус;
  район, формат и статус выбираются из списка, потому что дашборд группирует по ним напрямую.
  Через форму можно поставить и «Закрыта», и «Недвижимость» — бот такие статусы при заведении
  не предлагает намеренно.
- **Заявка** — человек, который хочет в домашнюю группу. Обязательны ФИО, вид и статус.
  Участника в боте у такой заявки нет, поэтому имя и телефон хранятся в самой заявке.

Проверки живут в `src/dashboard/forms.ts` чистыми функциями — они покрыты тестами без HTTP.
Маршруты `POST /groups/group/create` и `POST /groups/request/create` устроены как удаление:
только POST, живая сессия, затем разбор. Лимит тела 64 КБ: кириллица в URL-кодировке занимает
шесть байт на символ, и длинный комментарий иначе не прошёл бы.

Записи помечаются источником: `таблица`, `бот` или `ui`. В таблице дашборда ярлык показывается
только у неродных для выгрузки строк, и убрать со страницы можно только их — данные выгрузки
правятся в самой таблице, иначе следующий импорт вернул бы удалённое.

## Раздел «40 дней»

Всё, что показывала команда `/stats` в боте: сколько зарегистрировано и с полной анкетой,
сколько выдано наборов, сколько бросили анкету, сколько новых заявок, какой сегодня день
кампании. Плюс разрез по домашним группам участников и по платформам.

Сетка сорока дней показывает, где материал загружен, а где нет; текущий день обведён.
Загружать материал и отправлять рассылки по-прежнему в боте — отправлять сообщения умеет
только он. Ниже таблица доставки последних рассылок: сколько дошло, сколько в очереди,
сколько не дошло.

Считает всё `src/dashboard/campaignStats.ts` теми же репозиториями, что использовал бот,
поэтому цифры не могут разойтись.

## Правка и удаление в списках

В раскрытой строке — и у групп, и у заявок — есть «✏️ Править» и «🗑 Убрать». Правка
подменяет подробности формой с теми же полями, что и заведение: описание полей одно
(`GROUP_FIELDS` и `REQUEST_FIELDS` в скрипте страницы), поэтому подписи не могут разъехаться.
Удаление в два нажатия, мягкое: со страницы запись исчезает, в базе остаётся.

**Правка строки из выгрузки берёт её под управление дашборда.** Такая строка помечается
источником `ui`, и следующий импорт её не перезаливает — иначе правка бы потерялась. В строке
об этом написано прямо: «после правки строка перестанет обновляться из таблицы». То же при
удалении: иначе импорт вернул бы удалённое.

Импорт узнаёт такие строки по номеру в реестре, а если номера нет — по ведущему, формату и
району (у 32 групп из 116 номера нет). Проверено прогоном: правишь строку, удаляешь другую,
перезапускаешь импорт — 114 строк перезалились, 2 пропущены, правка на месте, удалённая
не вернулась.

## Ведение заявки

В раскрытой строке заявки есть быстрый выбор статуса и поле ответственного — это замена
команде `/close` из бота, самое частое действие. Перевод в «Исполнена» или «Аннулирована»
отмечается как обработка. Рядом «Править» для полной правки всех полей: два отдельных пути,
чтобы не гонять двадцать полей ради смены одного статуса.
Автором ставится «дашборд» — вход там по паролю, а не по id служителя, и приписывать
действие конкретному человеку было бы выдумкой.

## Выгрузка участников

`GET /groups/export.csv` — тот же CSV, что отдаёт команда `/export` в боте (общая функция
`usersToCsv` в `src/core/csv.ts`). В боте команда осталась.

## Удаление ведущего со страницы

У записей, заведённых через бота, в раскрытой строке есть кнопка «Убрать ведущего».
Нажатие первое предупреждает («Точно убрать N?»), второе — убирает; через четыре секунды
предупреждение снимается само. Удаление мягкое: запись пропадает со страницы, но остаётся
в базе с отметкой `archived_at`.

**Кнопка есть только у строк с ярлыком «бот».** У выгрузки из таблицы церкви нет `id`
в базе, и правится она в самой таблице — из дашборда её не удалить, и делать вид,
что можно, было бы обманом.

То же самое доступно в боте: `/leaders` → «🗑 Убрать».

Что защищает эту кнопку (`POST /groups/leader/delete`):

- только POST — по GET запись могла бы стереть любая картинка на сторонней странице;
- нужна живая сессия, иначе 401;
- кука `SameSite=Lax` на межсайтовый POST не отправляется, поэтому отдельный токен не нужен;
- `id` обязан быть целым положительным числом, иначе 400;
- повторное удаление отвечает 404, а не молчаливым успехом.

**Адрес запроса берётся из `window.HG_BASE`**, который сервер подставляет в страницу
рядом с `HG_LIVE`. Своими руками относительный путь тут писать нельзя: страница живёт
по адресу `/groups` **без косой черты**, поэтому относительный `leader/delete` разрешается
от корня в `/leader/delete` — запрос уходит на статику сайта и получает от неё 405,
не доходя до сервиса. Именно на это напоролась первая версия кнопки.

## Вкладка «Заявки»

Отдельный лист таблицы — «ЗАЯВКИ», 233 обращения человека, который хочет в домашнюю группу
(октябрь 2025 — август 2026). Живёт на своей вкладке в шапке и в «Обзор» намеренно не попадает:
это другой поток работы, а не срез по группам. На этой вкладке показатели по группам тоже
скрываются — им там не место.

Что на вкладке:

- **Сводка**: всего, исполнено, в работе, аннулировано, подобрана группа
- **Заявки по месяцам** — столбик на месяц, внутри доли по исходу (исполнены / в работе /
  аннулированы). Видно и объём потока, и что с ним стало. Пустые месяцы рисуются нулём,
  иначе график врал бы, будто потока не было вовсе. В легенде намеренно нет цифр: те же
  числа уже стоят в плитках, а третий повтор только сбивает
- **Возраст обратившихся** — по возрастным группам
- **Причины аннулирования**, **служение**, **ответственные**, **источники** — ранжированные бары
- **Таблица** со всеми заявками и фильтром по статусу; строка раскрывается кликом

Графики считаются по всем заявкам: фильтр статуса относится только к таблице, под которой
он и стоит. В подписях карточек всегда указано, у скольких заявок поле заполнено, — чтобы
никто не принял график по 65 строкам за картину по всем 233.

**Возраст приходится нормализовать.** В таблице его пишут как попало: «35-45 лет», «55-65»,
«37 лет», «40.0», «20+». Сводим к семи группам (`ageBucket`), что не разобрали — не рисуем,
но пишем в подписи, сколько таких.

**Одни и те же числа показываем один раз.** Сводка заявок — это пять плиток сверху,
и больше нигде те же величины не повторяются: воронку «поступило → подобрана группа →
ходит» убрали именно поэтому, её содержимое теперь в плитках («Подобрана группа» = 70,
под ней «дошли до группы 36»). Заодно ушло разночтение: в легенде графика «В работе» —
это три статуса вместе (112), а в плитке — только один (58); теперь легенда так и
подписана, «В работе и на контроле».

**Мусор в графе служения.** Там встречаются «???», «?», «не указала» — в графике это не
данные, а шум, поэтому берём только значения, где есть буквы. Сколько осталось, написано
в подписи карточки.

**Чего не стали строить.** Срок от заявки до рекомендации: обе даты заполнены всего у 7 заявок
из 233. График по 3% данных выглядел бы как факт, а был бы догадкой. Оживёт сам, когда
в таблице начнут заполнять «Дата рекомендации».

Переносятся все 16 заполненных столбцов листа. Столбец «!!!» пуст во всей таблице, поэтому
его нет. Одна особенность данных: в графе «ОТВЕТСТВЕННЫЙ» у 18 строк вместо имени стоит
статус «Аннулирована» — такие значения именем не считаем, иначе в разбивке по ответственным
появился бы человек с таким именем.

## Как обновить данные

Внутри файла есть строка `const DATA = {...}` — это весь набор. Пересобрать из свежего xlsx:

```bash
python3 tools/extract.py "путь/к/Домашняя группа (Ответы).xlsx" > data.json
```

Затем подставить содержимое `data.json` вместо объекта `DATA`. Структура записи группы:

```json
{
  "leader": "Иванов Иван", "district": "Приморский", "metro": "Пионерская",
  "people": 12, "coordinator": "Петров Пётр", "feedback_at": "2025-09-22",
  "format": "Основная церковь", "status": "Функционирует",
  "open_to_new": "ДА", "age": "35-50", "composition": "Смешанная", "day": "Четверг"
}
```

## Чего не хватает в исходных данных

**Дат открытия и закрытия групп.** В реестре записан только текущий статус, поэтому:

- блок **Equity** показывает текущий размер сети и честное пустое состояние вместо кривой роста;
- блок **«Закрытые группы»** показывает разрез по районам вместо динамики по месяцам;
- переключатели периода (1M/6M/1Y/3Y/5Y, Месяц/Год) отрисованы, но выключены.

Достаточно добавить в таблицу две колонки — `Дата открытия` и `Дата закрытия`. После этого графики
оживают без переделки вёрстки: логика читает их из тех же записей `DATA`.

Единственная настоящая временная ось в данных сейчас — **дата обратной связи координатора**
(79 групп, февраль 2025 — июнь 2026). По ней построен график «Обратная связь координаторов».

## Что интерактивно

- Клик по району на карте или в списке фильтрует весь дашборд, повторный клик снимает фильтр
- Фильтр по статусу группы над таблицей
- Сортировка таблицы по любой колонке
- Цель по числу групп редактируется прямо в карточке, значение переживает перезагрузку (localStorage; если хранилище запрещено — работает в пределах сеанса)
- Тултипы на карте, барах и точках графика
- Вкладки в шапке показывают срез: Обзор / Группы / Ведущие / География / Аналитика

## Карта

Схематичная: районы разложены плитками примерно по географии (север сверху, залив слева,
юго-восток снизу), заливка по числу групп. Так сделано намеренно — не нужны внешние тайлы,
ключи и лицензии, читается на телефоне и работает офлайн. Настоящие географические контуры —
отдельная задача, потребуется GeoJSON районов Петербурга.

## Перенос на React/Next.js + Tailwind

Файл писался с прицелом на это:

| В файле | В React |
| --- | --- |
| CSS-переменные в `:root` | токены в `tailwind.config.ts` (`colors`, `borderRadius`) |
| `.card`, `.kpi`, `.pill`, `.seg`, `.rank` | компоненты `Card`, `KpiCard`, `StatusPill`, `SegmentedControl`, `RankBar` |
| `state` + `renderAll()` | `useState` + производные значения, без ручного перерендера |
| `visible()` | селектор/`useMemo` над списком групп |
| SVG-график в `renderFeedback()` | тот же расчёт, но в JSX; библиотека графиков не нужна |
| `DATA` | ответ API или серверный компонент |

Палитра: фон `#08090A`, карточки `#0F1011`, границы `rgba(255,255,255,.07)`, акцент `#5E6AD2`,
семантика `#3FB950` / `#D29922` / `#F85149` / `#6E7681`. Шрифты: Manrope (интерфейс),
JetBrains Mono (цифры).
